# 2026-11-01

## 修复：日常记录删除入口不可见（用户反馈「没有删除功能」）

**根因**（不是逻辑缺失，是 CSS 藏死了按钮）：
- `.row-x` 基础样式是 `opacity:0; pointer-events:none`，只在显式列举的父行 hover 时显示
- 那份选择器清单里有 `.task/.hrow/.trivia-row/...`，但**漏了 `.rrow` 和 `.log-row`**
- 抽屉里的「删除这个事项」还排在全部记录之后，记录一多要滚到底才看得到

**改动**：
1. `ui/styles.css` 显示清单补 `.rrow:hover/.rrow:focus-within/.log-row:hover/.log-row:focus-within`
2. 日常记录行删除按钮改为**常驻淡显** `opacity:.34`，hover/聚焦变 1；`.rrow` 网格固定留 36px 列，去掉 hover 时的列宽跳变与 `.rrow-x` 的 `overflow:hidden`
3. `ui/app.js` 抽屉把「删除这个事项」从末尾移到「记一次」旁边（`drawerRoutine`），并修正随之少掉的一个 `</div>`

**验证**：新增 `mercury-delete.js` 专项测试 21 项（样式规则、每行都有删除入口、div 闭合平衡、删除→确认→回收站→Ctrl+Z 撤销、单条记录删除与原位恢复），加上原有 36 项冒烟测试全过。
重编译 release exe / nsis 安装包 / debug exe，brotli 解压逐字节比对确认 js+css 均已嵌入。

**项目机制备忘**：`tauri.conf.json` 只有 `frontendDist: "../ui"` 没有 `devUrl`，前端资源在**编译期**打包进 exe，改完 `ui/` 必须重编译才生效，且 `npm run dev` 也无热更新。
